## Actionable findings

1. **P1 — stale resolver pins the previous responder's voice to the new responder.** `services/inbox-watcher/inbox_watcher.py:2965-2986,2993-3016`. `_cue_voice` captures `identity` before `_voice_choice(m)` (catalog/profile lookup without `mu`), then stamps the *old* choice with the memo's *current* stamp and publishes it without rechecking the responder. `_reply_voice` repeats this with a pre-lock `stamp` and stale choice, but stamps `identity` from the current memo after lookup. Scratch reproduction `stale_resolver_different_responder` changed `agent/command_id` under `mu` while a mocked slow lookup returned tile-a/carlin: final lock became `{voice:carlin, identity:[cmd-b,tile-b]}`, and a second `_reply_voice` returned carlin even though current registry assignment for tile-b was brule. `stale_cue_slow_resolver_new_responder` independently rendered a progress cue in carlin for cmd-b/tile-b. Make identity/stamp/lock generation validation atomic with lock publication; discard/re-resolve stale lookups, including cue path, and test real callback interleavings.

2. **P1 — late cue fallback can mutate a pending cue lock after the final lock has won.** `services/inbox-watcher/inbox_watcher.py:2968-2986,3024-3045,3048-3077`. `_cue_voice` checks `voice_lock` only *before* the unlocked lookup. In scratch reproduction `delayed_cue_creation_after_final_lock`, the final reply pinned carlin while a cue lookup was paused; the resumed cue installed an independent `cue_voice_lock` carlin. A simulated 404 via real `_missing_voice(...,cue=True)` then mutated pending to rick and returned rick, while the rendered final lock remained carlin. The final-lock priority check is absent from the publish/fallback critical sections. Recheck final lock before inserting cue lock and before fallback; discard stale cue work rather than rendering a mixed-voice cue. Final lock itself was **not** overwritten in this reproduction; the defect is divergent pending/cue audio after final.

3. **P2 — path validation has a time-of-check/time-of-use symlink window.** `services/inbox-watcher/converse.py:1715-1719,1751-1767`. `ProfileVoice.resolve` checks `(root/name/config.yaml).resolve()` against `root`, then `CardCache.profile_config` stats and reads by pathname. Scratch reproduction `profile_symlink_swap_after_validation` replaced the in-root config with a symlink to a scratch file outside the rendered profiles directory between validation and read: the adapter accepted voice `walken` from the outside file, with no credential content leaked. Requires filesystem mutation at this boundary, so lower priority; read securely from a bound file descriptor with no-follow checks, or compare post-open inode and canonical path before accepting config. Preserve sanitized fallback.

4. **P2 — final render completion does not revalidate responding identity.** `services/inbox-watcher/inbox_watcher.py:3115-3123`. `_voice_rendered` checks stamp and lock_id but not `choice.identity` against `_voice_identity(m)`. Scratch `responder_change_during_final_render` switched agent/command_id under `mu` while mocked synth was paused; completion succeeded, with rendered carlin lock for `[cmd,tile-a]` but current memo identity `[cmd-b,tile-b]`. Gate rendered completion and downstream upload on identity; do not treat the lock id alone as proof of current responder. If product flow guarantees responder immutability after synth starts, enforce/document it and test the guarantee rather than relying on it implicitly.
