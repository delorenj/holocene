# HOLOC-58 local fulfilment verification

The Live reader accepts only the exact declared `uv run scripts/licensing/issuer.py ... snapshot` argv, a separate `LIVE_FULFILMENT_READONLY_KEY_REF` (not the sales key), and `LIVE_FULFILMENT_TRUSTED_REPO`: an operator-approved **absolute, canonical, non-symlink** path to the owner-controlled Earshot checkout. The registered project's canonical path must match the approved path exactly; the issuer script must be a regular file, not a symlink, resolving inside that checkout. Execution replaces the relative script argument with this approved absolute path. Missing approval or mismatched roots return `unavailable`; legacy `outstanding` never runs. No machine-specific checkout path is baked into code or service configuration here. Set approvals only after the owner reviews the accepted source and restricted key; this checkpoint does not set them for production.

This is source **identity and owner trust**, not a sandbox or immutable digest: code in the approved checkout, its imports, or uv environment remains capable of side effects under the API account. The committed fixture regression runs real `defaultLiveDeps.run`/uv on a private scratch script, binds `deps.home` to the script's asserted ledger/catalog paths, and checks ledger bytes/mode/times and directory entries. Negative controls register an unrelated repo with identical argv and a symlinked issuer; neither executes. It does not invoke or prove the real Earshot issuer under real provider/ledger credentials. Independent upstream source review remains required before approving the checkout.

Earshot's snapshot measures relative `due_in`/`overdue_by` before its provider scan and emits no measurement timestamp. The API captures its invocation time as a conservative lower bound for measurement and compares the derived deadline to subprocess completion; a delayed read cannot extend the original payment deadline. This bound can mark an order overdue early by the interval before upstream measurement; exact timing requires a source-owned timestamp in a future contract. A zero-second due at an instantaneous read remains due; one second past the bound becomes overdue. The browser advances source age from `checkedAt` (or `generatedAt` minus server-reported age), reusing its existing render clock for chips, keys, and status. Retained payloads cannot remain fresh indefinitely after failed polls; the statement names the API outage rather than asserting all clear.
