# HOLOC-34 — one-file reply / manual retry race

## Observed failure and cause

The reported `mise run memo:test` run (`~/.local/state/holocene-auto/test-runs/memo-test-20261117T141754Z.log`, lines 3556–3557 and 4952–4966) failed the one-file test at its second-replied wait: after the first `replied`/`done`, the watcher logged `retry_refused` for `s3-one-file.ogg` (`memo is failed at done, not failed`), and the memo remained failed. That log directly supports rejection of the control request, not a broken voiced/replied fact. Source confirms the causal window: `_exec` releases the memo key from `w.running` in its `finally` block under `w.mu` (inbox_watcher.py:1440–1451), after the mirror stage can publish `replied` and mark `done`; `_control_retry` rejects a key still in `running` (1235–1241). The test had treated `status == done` as proof the worker was gone, then immediately set failed and issued `memo:retry`. Competing load increases the opportunity to hit that window; it is not proof that the decision pool itself is defective. HOLOC-30's bounded wait for a different `phone:{key}` retry-worker slot is precedent, not evidence that this test's phone retry worker caused the failure.

## Change and coverage

In `services/inbox-watcher/test_inbox_watcher.py`, wait for **this memo key** to leave `w.running` under `w.mu` after the first completed reply, before setting up the manual retry. The wait has a monotonic 10-second deadline and reports the key, stage, and status if the worker does not finish. It does not change runtime code, test skips, assertion strength, or the existing 200-tick retry wait. The test still checks one `voiced` with chunk 1/1 and both audio keys equal to `replied.reply_s3_key`, `reply_chunks is None`, exact `voiced` then `replied` fact order, timing metadata, retained `voiced_one`, two replied facts after the manual retry, and no second voiced fact. A wrong order or duplicate voiced fact fails the existing equality/count assertions.
