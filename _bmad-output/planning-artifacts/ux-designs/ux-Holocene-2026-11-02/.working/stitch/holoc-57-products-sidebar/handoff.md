## Recommendation to owning PM, not a selection

**Choose the Ledger visual arrangement of A plus the single-column directory hierarchy of C** as an implementation direction, with these corrections. A fits the actual Ledger/Ledger night app better than the older unselected Spruce designs. C keeps long labels and three launch entries in a vertical reading order; a labelled menu can expose the same hierarchy on a phone. Use a persistent ~232px desktop sidebar and modal phone drawer, Products prominent, with launch/live subset links and Workspace, Media, System disclosures. Use explicit receipt provenance and bounded missing/unavailable/error rows rather than replacing lifecycle authority with URLs.

**Reject mock data and faux certainty:** desktop A invents a date, counters/telemetry, event numbers and brand phrases; phone C invents product IDs (`TOLT-26`, `GIB-09`, `GRV-44`), a `verified` receipt badge, a checksum/manifest claim and 'Responsive wrap certified'. None are sourced. Phone's Earshot action is `#/live` (wrong; use real `/live`). Several generated HTML links are `#` (inert). A includes source-free launch actions and an output screen screenshot larger than its requested CSS viewport. Canonical product identity and display copy must come from PJ/declarations; URL only from validated receipt. No invented health, metrics or publication verification. Both concepts use external script/asset hosts and have no auth behavior; don't ship their HTML.
